# The stack bound's notes for RP2350 images (Kvasir_SDK cmake/tools/stack_bound.py; directives: its docstring).
#
# The boot ROM: 32 kB at 0x00000000 (RP2350 datasheet 4.1 "ROM"). Its functions are found through rom_table_lookup_val(),
# a 16-bit pointer at 0x00000016 (5.4.1 "Locating the API functions", the bootrom contents table). They run on the
# caller's stack, and the datasheet gives no figure for it (5.4: none for the Arm functions). The budgets below are
# measured on the ROM itself: chip_rp2350/tools/rom_stack.py over a dump read over SWD - the deepest path of each entry,
# frames read from its code, nothing it calls left unresolved. An image runs on whichever revision the chip has, so each
# budget is the larger of the revisions measured:
#
#   function                          A2      A4    budget
#   lookup (0x16)                      8 B     8 B     8 B
#   connect_internal_flash IF         36 B    52 B    52 B
#   flash_exit_xip EX                 80 B    80 B    80 B
#   flash_flush_cache FC               0 B     0 B     0 B
#   flash_range_erase RE             112 B   104 B   112 B
#   flash_range_program RP           104 B   104 B   104 B
#   explicit_buy EB                  168 B   184 B   184 B
#   flash_runtime_to_storage_addr FA  12 B    12 B    12 B
#   flash_op FO                      216 B   208 B   216 B
#   get_partition_table_info GP      176 B   176 B   176 B
#   get_sys_info GS                   96 B   108 B   108 B
#   otp_access OA                     80 B    80 B    80 B
#   reboot RB                         40 B    60 B    60 B
#   flash_select_xip_read_mode XM      0 B     0 B     0 B
#   load_partition_table LP: a LOWER BOUND on both (its code reaches calls the tool cannot follow) - no budget
#
#   A2: version byte (0x13) 2, SHA-256 196c503fbb17b2ad21a1f496574786af698f9376af9a5f79e5e75293c9e12191
#   A4: version byte 4, SHA-256 cb681bd21bb6ecf63326ec56a2e212c872760574661b796e8443b2dccf8a0b3b (two boards, identical)
#
# A3 is not measured: on an A3 these hold only once rom_stack.py has run over its ROM (it prints the version and the
# hash). A function below without a byte count stays a LOWER BOUND, and the report names each caller.
rom_region 0x00000000 0x00008000
rom_pointer 0x16
